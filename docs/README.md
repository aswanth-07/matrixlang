# MatrixLang documentation

Which document answers which question.

| Document | Read it for |
| --- | --- |
| [language-reference.md](language-reference.md) | What the language *is*: tokens, grammar, shape rules, every diagnostic, the VM instruction set. The definition `matrixc` is checked against. |
| [design.md](design.md) | Why the code is shaped the way it is. Decisions, trade-offs, and the bugs worth remembering. |
| [phase1-design.md](phase1-design.md) | Review 1 deliverable: title, abstract, problem statement, motivation, objectives, scope, background study, architecture, technology stack, prototype. |
| [phase2-implementation.md](phase2-implementation.md) | Review 2 deliverable: each frontend module, what it does, and its real output. |
| [phase3-optimization.md](phase3-optimization.md) | Review 3 deliverable: the optimizer passes, measured results, target code, the VM, testing and limitations. |
| [REPORT.md](REPORT.md) | The final project report, in the eleven-chapter structure the lab manual specifies. Cross-references the three phase documents rather than repeating them. |
| [../paper/matrixlang.pdf](../paper/matrixlang.pdf) | The paper: the argument the project makes, the evidence for it, and what it does not claim. Source in `paper/matrixlang.tex`, built by `make paper`. |
| [teaching-exercises.md](teaching-exercises.md) | Proposed exercises and rubric for shape rules, cost objectives, numerical legality, and independent checks. |
| [../paper/README.md](../paper/README.md) | Research protocol, evidence map, reproduction, and venue/author checklist. |

## Directories

| Path | Contents |
| --- | --- |
| `figures/` | Generated figures. `architecture.png` is built by `tools/build-architecture-figure.py` and embedded in both the report and the submission document. |
| `submission/` | Deliverables in the format the department accepts. `MatrixLang-Phase1.docx` is generated by `tools/build-phase1-docx.js`, `MatrixLang-Phase2.docx` by `tools/build-phase2-docx.js` (with `MatrixLang-Phase2.pdf` converted from it by LibreOffice), `MatrixLang-Deck.pptx` by `tools/build-deck.py`, and `MatrixLang-Implementation-Review.pptx`, the seven-slide implementation review deck whose every transition is PowerPoint Morph, by `tools/build-review-deck.js`. |

Both are regenerable. They are committed anyway because a submission deadline is
a poor time to discover that a generator needs a toolchain you no longer have.

The Phase 1 and Phase 2 Word/PDF deliverables are historical laboratory snapshots.
Their listings describe that review's implementation. Use the language reference,
current source and research artifact for the final numerical contracts and
evaluation; the laboratory snapshots are not evidence for the paper's results.

## Regenerating

```bash
python tools/build-architecture-figure.py docs/figures/architecture.png
node   tools/build-phase1-docx.js          docs/submission/MatrixLang-Phase1.docx
node   tools/build-phase2-docx.js          docs/submission/MatrixLang-Phase2.docx
soffice --headless --convert-to pdf --outdir docs/submission docs/submission/MatrixLang-Phase2.docx
make deck      # docs/submission/MatrixLang-Deck.pptx
make review-deck  # docs/submission/MatrixLang-Implementation-Review.pptx
make web       # demo/data.js, for the web demonstration
make measure   # two-seed development results for the deck and demo
make research  # expanded paper evaluation and generated tables/figure
make paper     # named and anonymous manuscript PDFs
```

The figure script needs Pillow; the document script needs the `docx` npm
package; the review deck needs the `pptxgenjs` and `qrcode` npm packages and
`pdftoppm`; the deck and demo generators need only the Python standard library.
The plotting scripts need the pinned matplotlib environment in `requirements.txt`.

Generated statistical displays read recorded results, and compiler captures read
`bin/matrixc`. The laboratory deck and demonstration retain development seeds
1 and 2; the paper uses the separate `results/research` protocol.
