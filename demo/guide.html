A seven-minute demonstration

Show how static matrix shapes connect semantic analysis, optimization cost and numerical contracts. Keep the source visible while moving through the compiler stages.

Start the local compiler

make serve
# Open http://127.0.0.1:8731/

The workspace reports Local compiler ready. Use Compile & run after editing. On a static host, the five unchanged examples show recorded compiler output; edited programs receive browser lexical and syntax analysis only.

Presentation increases code size. Ctrl+Enter compiles; Ctrl+Shift+Enter compares both modes. Arrow keys move between stage tabs. Tab leaves the editor; Ctrl+] inserts two spaces.

Matrix product · 90 seconds

Open Matrix product. Point to the declarations and matrix C = A * B;. The compiler infers Matrix<2x4>.

Inspect Shape check, Symbols, TAC, VM code and Execution. The result is computed by the compiler's typed stack VM. Tokens and Syntax tree expose the front end.

Shape mismatch · 60 seconds

Open Shape mismatch. A 2x3 matrix cannot multiply a 5x4 matrix. Read the two operand shapes and the inner-dimension rule in the diagnostic.

Use the diagnostic's line link to locate the expression. On the local server, change B to matrix B[3,4]; and compile. Observe acceptance and the newly generated code.

Chain ordering · 90 seconds

Open Chain ordering. Strict mode keeps (A * B) * C and its 69,800 modeled operations. Select Algebraic: the optimizer emits A * (B * C), costing 1,396 modeled operations.

The TAC instruction count remains four. Explain the formula m*p*(2*n-1) for a matrix product. Reassociation changes intermediate dimensions; it does not change the number of product instructions. These values describe conventional arithmetic work, not elapsed runtime.

Expression reuse · 60 seconds

Open Expression reuse. Both X and Y use A * B. Compare TAC and Optimization; read the common-subexpression rewrite and inspect the resulting values under Execution.

Signed zero · 60 seconds

Open Signed zero and choose Compare modes. Strict optimization preserves the source execution's negative zero. Algebraic zero multiplication permits positive zero.

The comparison uses hexadecimal binary64 output, which distinguishes signed zero. This is a concrete reason for separate numerical contracts; the example does not establish universal strict correctness or an algebraic accuracy bound.

Parser walkthrough · 60 seconds

Open the front-end walkthrough to step through scanner rules, shifts, reductions and syntax recovery. Its LALR table is exported from Bison. Return to the workspace to inspect the remaining compiler stages.

The project has static shapes and straight-line programs. It has no loops, functions or dynamic shapes. Its research evaluates generated workloads and numerical fixtures; classroom learning outcomes remain unmeasured.
