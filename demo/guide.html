The demonstration

Show how declared input domains let the compiler decide, for each rewrite, which floating-point guarantee it keeps, report it for every printed output, and turn the proof into measured speed against NumPy and GCC. The full script, contrasts and answers to likely questions are in docs/demo-notes.md.

The title bar reports Local compiler ready; edited source then compiles with matrixc, and Run on this laptop in the Race view times every contestant live. Without the service, every view works from results recorded on this laptop.

The presenter strip at the bottom steps through the five-minute path: → and ← move between steps whenever the cursor is not in the editor. Ctrl K opens the command palette. Ctrl Enter compiles; Ctrl Shift Enter compiles under all three contracts and compares them.

The five-minute path

  1. Opener. Python's own floating-point results drawn as bits: reordering changes the answer.
  2. Shapes before code. Matrix product: inferred shapes, rejected mismatches.
  3. Proved exact. Exact integer chain under strict: 11,120 → 556 operations, certified bit-identical.
  4. Bounded. Real-valued chain: strict refuses, bounded reorders within a stated error bound.
  5. Race: graph walks. MatrixLang on one side, NumPy and GCC on the other, timed on this laptop.
  6. Race: diffusion. Real data: a certified bound against silent bit changes.
  7. Race: overflow trap. multi_dot returns infinity; MatrixLang keeps the finite answer.
  8. Results. Speedup, bits and guarantees on one screen.

The three contracts

A contract names the weakest guarantee a value-changing rewrite may have and still be applied.

  • Strict (default): a rewrite applies only when facts derived from the declared input domains prove its result bit-identical to the source program.
  • Bounded: also applies rewrites that keep the source order's standard-model worst-case error bound and its NaN and infinity behaviour. Signed zeros and low-order bits may differ.
  • Algebraic: applies any rewrite valid over the real numbers.

The Guarantees stage lists each print with the level it was certified at: bit-identical, bound-preserving or relaxed. With the local compiler, every certificate is checked against an unoptimized run on inputs drawn with the selected seed.

Exact integer chain · 90 seconds

Open Exact integer chain. A, B and C are declared input(int8); the compiler sees only the domain, never the values. Under Strict, the Guarantees stage states that every intermediate of every bracketing needs at most 28 of binary64's 53 significand bits, so A * (B * C) computes the same bits as (A * B) * C.

Optimization shows the modeled arithmetic falling from 11,120 to 556 operations under the strict contract. The formula is m*p*(2*n-1) per product; these counts describe arithmetic work, not elapsed runtime.

Real-valued chain · 90 seconds

Open Real-valued chain. The same shapes over input(real(1)). Products of reals round, so Strict keeps the source order and its 11,120 operations. Select Bounded: the optimizer applies the cheaper order and certifies |error| <= 4.66e-15 |A1|...|Ak|, a bound every bracketing satisfies.

Choose Compare contracts. Strict output equals the unoptimized run; bounded and algebraic output differ in low-order bits, which their certificate permits.

Unbounded reals · 45 seconds

Open Unbounded reals. With input(real) no magnitude bound exists, so an intermediate may overflow and no bracketing provably keeps the error bound. Strict and bounded both keep the source order; only Algebraic reorders, and it certifies the output as relaxed.

Per-output guarantees · 60 seconds

Open Per-output guarantees under Bounded. One program, two outputs: the int16 chain R is certified bit-identical, while S, which multiplies real-valued data, is certified bound-preserving. A single fast-math switch cannot express this distinction.

Signed zero · 60 seconds

Open Signed zero and choose Compare contracts. -2 * 0 is -0 in IEEE 754. Strict keeps the multiplication and prints -0x0p+0; bounded and algebraic replace it with 0, print 0x0p+0, and certify the output as bound-preserving rather than bit-identical.

Hexadecimal binary64 output distinguishes every value, including the sign of zero.

Inherited guarantee · 45 seconds

Open Inherited guarantee under Bounded. The inner 0 * N may be -0 and is rewritten to +0 as a bound-preserving rewrite; the outer 0 * T is then provably +0, but only because of the inner rewrite. Once the outer rewrite removes the inner product, its label would be lost; the certificate of print(R) inherits it and reads bound-preserving. The evaluation found this defect in an earlier version.
