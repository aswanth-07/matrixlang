Exactness threshold explorer

The chain theorem, evaluated in the browser

For a chain over int(0,m), every proper sub-chain must be exact in binary64: mk · n1⋯nk−1 ≤ 253, where the n are its inner dimensions. The whole chain may round once, in its final sums, if for every split every sum of all but one of the last product's terms still fits. Every bracketing, in any order of summation, then prints the correctly rounded product. Strict reorders a segment only when that holds. Enter shapes and a bound to see the test the compiler applies.

Dimensions d0, …, dk of a k-operand chain: operand i is di−1 × di.

RQ1 · How much optimization does each contract recover?

Modeled arithmetic removed per value domain under each contract. No proofs is the previous strict optimizer, which refused every value-changing rewrite; recovery is the share of the algebraic saving that a contract obtains with proofs.

RQ2 · Are the certificates sound?

Each output of each executed program is compared, bit for bit, with the unoptimized program on the same drawn inputs, and with the guarantee the certificate states for it.

This study found one defect, since fixed: a rewrite proved bit-identical from facts that held only because an earlier bound-preserving rewrite produced them, after which dead-code elimination removed the weaker rewrite and its label. Rewrites now inherit the weakest guarantee of the definitions their proof reads; the Inherited guarantee example shows the case.

RQ3 · How tight is the threshold?

The compiler's threshold, found by binary search on its own certificates, against the closed form and against the earlier condition that the whole chain be exact; then witness inputs on which the refused bracketing prints different bits. Besides all-maximum, near-maximum and seeded inputs, a search emulates the virtual machine's arithmetic and lowers a few maximal entries so that a partial sum before the last is odd and above 253; every witness is confirmed by matrixc.

RQ4 · What is a certificate worth to a C compiler?

Six kernels written as the mathematics is written, compiled by matrixc to C (--emit-c) and by GCC. Proved chain reorderings carry the speed; the reduction clauses the facts license keep every build's bits identical on integer data.

Hand-written reductions

The same reductions compiled by GCC with strict IEEE semantics and with reassociation licensed (-fassociative-math -fno-signed-zeros -fno-trapping-math). On certified integer-valued data the two builds print identical bits; on the real-valued control they do not.

RQ5 · Which tests notice a missing side condition?

Tests killed per mutant: each mutant removes one proof obligation of the strict contract. Small-integer (dyadic) programs are exact under every association, so they cannot notice a compiler that reorders without proof.

RQ6 · Is the cheaper bracketing more accurate?

Preregistered study: real-valued chains with exact integer references, evaluated in the compiler's own summation order (validated bit for bit against matrixc). Paired two-sided sign tests with Holm correction; median error ratio with seed-cluster bootstrap 95% intervals. The equal-cost ablation pairs bracketings of identical modeled cost.
