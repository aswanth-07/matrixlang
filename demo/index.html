Shapes in theType System

A matrix language that lets a compiler course reach optimization.

A compiler project is usually built for a subset of C, and the choice is rarely examined. In a general-purpose mini-language the type system is an enumeration with two members, so semantic analysis reduces to comparing two tags and the optimizer has only the scalar identities to work with. Put matrix shapes in the types instead and the compiler can cost a program before it runs.

The whole argument, in six lines

matrix A[100,2];
matrix B[2,100];
matrix C[100,2];

matrix R = A * B * C;
print(R);
69,800 FLOP as written, left to right
1,396 FLOP as the compiler emitted it
4 instructions, either way

Matrix multiplication is associative, so both bracketings compute the same matrix. They do not perform the same amount of arithmetic, and which is cheaper depends only on the shapes.

Rules that match here longest wins

flex tries every rule at the cursor and keeps the longest match; a tie goes to whichever rule comes first in matrix.l. That single sentence is why matrix is a keyword and matrixx is not: on matrix the keyword rule and the identifier rule both match six characters and the keyword rule is earlier, while on matrixx the identifier rule matches seven and wins outright.

Why an instruction count cannot see this

            
A chain
              of k matrices needs exactly k-1 products
              under every bracketing, so re-bracketing never changes the
              instruction count. It is invisible to the metric course projects
              conventionally report, which is the whole reason this project
              measures arithmetic instead.

            

              This explorer runs the same formulae as
              src/ir/cost.c and src/ir/chain.c,
              re-implemented in JavaScript so it can respond as you type. The
              compiler itself is C, and the figures elsewhere on this page come
              from running it.

Phases present, of eight

          

            
CompilerPhases

            
          

          

            Three public C-subset course projects, chosen by their description
            before their contents were read, each reduced to its most complete
            version. A phase counts as present on a single case-insensitive
            match of any of its markers, a rule generous enough that it can
            only overstate a baseline. None of the three contains an optimizer,
            and none executes anything.

        

        

          
What the testing found

          
unoptimized          optimized
R = Matrix<1x1>      R = Matrix<1x1>
  [ 0 ]                [ -0 ]

          

            One generated program in the first run disagreed. The cause was the
            rewrite 0 - x => -x: true over the reals, and not
            observationally equivalent in IEEE-754, because +0
            minus +0 is +0 while negating
            +0 gives -0.

          

            That floating-point identities break this way is textbook. What is
            worth reporting is that a generator and a loop comparing two runs
            — a weekend of work — found a defect in a student-scale
            optimizer that reading the code had not, on an input nobody chose.
            The rewrite was removed.

        

      

    


    
    

      

        
06 · Scope

        
What the domain bought, and what it did not

        
The claim is that the source language is a curricular
          decision: it decides which phases can carry real work. That is the
          claim we can evidence, and it is the only one we make.

      


      


      

        

          
What it bought

          
    
            
  • +
    Semantic analysis
              became shape inference and dimension checking, not a comparison
              of two type tags.
    • 
            
  • +
    Code generation
              gained instruction selection driven by inferred types.
    • 
            
  • +
    Optimization
              gained transformations worth applying and a cost model to score
              them with.
    • 
            
  • -
    It costs control-flow graphs and dataflow
              analysis. MatrixLang has no branches, which is the enabling
              decision and also the honest limitation.
    • 
          

        

        

          
What we do not claim

          
    
            
  • x
    That students learn more. The language has
              not been taught to a cohort yet, so there is no learning
              outcome here to report.
    • 
            
  • x
    That the mechanisms are new. Shape-typed
              array languages, chain ordering and differential testing are all
              established; the contribution is the curricular consequence.
    • 
            
  • x
    That the magnitudes generalise. The corpus
              comes from a generator written for this project, so its
              distribution of shapes is a choice, not a sample.
    • 
            
  • x
    That three repositories are a sample of
              teaching compilers.
    • 
          

        

      


      

        Whatever the domain, if the type system carries enough to cost a
        program statically, a student's optimizer can be scored on the work it
        removes rather than the lines it removes. The two are not close.
