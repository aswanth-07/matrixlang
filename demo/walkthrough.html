Shapes in theType System

Inspect shape checking and optimization in a matrix language compiler.

Matrix shapes connect type checking to a static arithmetic model. This compiler exposes that connection across its phases. Strict optimization preserves association; explicit algebraic mode permits numerical changes to reduce modeled work. The figures below describe the two-seed development corpus. The expanded research study includes ablations and shape controls.

Matrix-chain example

matrix A[100,2];
matrix B[2,100];
matrix C[100,2];

matrix R = A * B * C;
print(R);
69,800 FLOP as written, left to right
1,396 FLOP as the compiler emitted it
4 instructions, either way

Matrix multiplication is associative over real numbers. Algebraic mode permits this cheaper tree; rounding, signed zero, and NaN/Infinity output may change. Strict mode retains the source association. FLOP here is a conventional arithmetic model, not measured runtime.

What flex does with the match

Rules that match here longest wins

flex tries every rule at the cursor and keeps the longest match; a tie goes to whichever rule comes first in matrix.l. That single sentence is why matrix is a keyword and matrixx is not: on matrix the keyword rule and the identifier rule both match six characters and the keyword rule is earlier, while on matrixx the identifier rule matches seven and wins outright.

Arithmetic cost and instruction count

            
A chain
              of k matrices needs exactly k-1 products
              under every bracketing, so re-bracketing never changes the
              product-instruction count. This project reports both instruction
              and modeled arithmetic reduction.

            

              This explorer runs the same formulae as
              src/ir/cost.c and src/ir/chain.c,
              re-implemented in JavaScript so it can respond as you type. The
              compiler itself is C, and the figures elsewhere on this page come
              from running it.

Signed-zero regression

          
unoptimized          optimized
R = Matrix<1x1>      R = Matrix<1x1>
  [ 0 ]                [ -0 ]

          

            One generated program in the first run disagreed. The cause was the
            rewrite 0 - x => -x: true over the reals, and not
            observationally equivalent in IEEE-754, because +0
            minus +0 is +0 while negating
            +0 gives -0.

          

            The regression test now covers this signed-zero difference.
            The rewrite was removed. The compiler defaults to strict mode, with explicit
            algebraic mode for transformations that can change output. The
            paper's broader evaluation and numerical fixtures are linked from
            the repository.

        

      

    


    
    

      

        
Scope and limitations

        
MatrixLang connects shape checking, modeled cost and
          numerical rewrite legality in an inspectable compiler. These are
          concrete artifact capabilities; their educational effectiveness
          remains to be measured.

              includes shape inference and dimension checking.
